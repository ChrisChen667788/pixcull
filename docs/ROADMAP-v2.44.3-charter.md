## 1. 结构假设成立,但结果全是 0

加 `spk_model="cam++"` 后 `sentence_info` 确实出现了,键是
`['end','spk','start','text','timestamp']` —— 适配器第一层的字段映射写对了。

**但 5 段全是 `spk=0`,两个说话人没分开。**

排查过程(每一步都在排除一个解释):

| 试的东西 | 结果 |
|---|---|
| 两个真实音色(Tingting / Meijia) | 全 0 |
| 把其中一路降八度(声学差异拉满) | 全 0 |
| 传 `preset_spk_num=2` 显式告知人数 | 全 0 |
| 加 0.7s 换手停顿让 VAD 能切段 | 全 0 |

于是探到聚类调用点,打印它收到什么:

```
嵌入 shape=(17, 192)  oracle_num=2
两两余弦相似度: min=0.250 max=0.906 mean=0.579
返回 labels=[0,0,0,...]
```

**17 个明显可分的嵌入 + 明确告知 2 人 → 仍返回一个簇。**

## 2. 根因在上游,而且是硬编码

`funasr/models/campplus/cluster_backend.py`:

```python
def forward(self, X, **params):
    k = params["oracle_num"] if "oracle_num" in params else None
    if X.shape[0] < 20:
        return np.zeros(X.shape[0], dtype="int")
```

**少于 20 个嵌入就直接返回「所有人都是 0 号」,在看嵌入和 `oracle_num`
之前。** 所以前面四次尝试全部注定失败,与素材和参数都无关。

造 59s / 24 轮的对话(78 个嵌入)复测:

```
嵌入 (78, 192) → labels 有 0 和 1 两类
```

按「这句话原本是谁说的」对齐:**纯单人片段 18 条,标对 18 条 → 100%**。
另有 3 条是标点模型把两人的话并进了同一段,单一标签本就不可能正确。

**说话人分离是好用的 —— 前提是片子够长。**

## 3. 产品决策:不把「分不出」说成「就是一个人」

这是本版最重要的一条。

FunASR 在两种完全不同的情形下输出**完全相同**:

1. 确实只有一个人说话;
2. 片子太短,聚类器**根本没试**。

如果适配器照单全收写成 `speaker="0"`,就是在**报告一个模型从未做出的
结论** —— 和「空转录冒充静音」是同一类安静的错误。

所以:**所有段标签相同时,一律置 `speaker=None`** 并记一条说明。
`None` 在两种情形下都为真:没有人被区分开。单人片子不因此损失什么,
因为本来就没有第二个人要区分。

CLI 端对应:分出来了报「2 speaker(s) distinguished」,没分出来**明说
「no speakers distinguished」并给出原因**,而不是显示一个 0 号说话人。

## 4. 其他两处

- **模型缓存按配置区分**。`spk_model` 会改计算图,复用不带它的缓存实例
  就得不到说话人。仍只保留**一个槽位**、换配置时重建 —— 同时驻留两份要
  多花 1.6 GB,省下的是一个会话里没人做第二次的加载。
- `--speakers` 为 opt-in:多一个模型、多一次加载,只对多人素材有意义。

## 5. 变异测试:第一轮漏掉一条,补上了

三条变异,第一轮只红了两条:

| 变异 | 第一轮 | 补测后 |
|---|---|---|
| 模型缓存不按配置区分 | 变红 ✓ | ✓ |
| 偷改上游阈值常量 | 变红 ✓ | ✓ |
| **去掉守卫的调用点** | **仍绿** | **变红 ✓** |

原因:所有断言都在**直接调用** `_drop_indistinct_speakers`,**没有一条
测试适配器是否真的调用它**。这正是仓库里记过的「改了守卫没跟消费方」。
补了三条驱动适配器本身的测试(桩模型返回全同 / 有别 / 未开启)。

## 7. 顺延

- **真实婚礼素材上的引擎对比** —— 仍待 owner。所有数字至今来自 macOS TTS:
  无噪声、无重叠说话、无口音(除台湾腔)。真实婚礼录音含第三方人声,
  属于 PII,取用范围要 owner 定。
- 说话人标签还没接进网页转录面板(CLI 与 JSON 已有)。
- `preset_spk_num` 未对外暴露:在 <20 段时它无效,在 ≥20 段时自动聚类已
  正确,**目前没有证据表明加这个开关能改善什么**,不做。
