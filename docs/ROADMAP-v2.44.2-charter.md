# v2.44.2 charter — 一键出片:文字剪到成片闭环

v2.44.1 之后剪辑结果只能导 EDL(进 Premiere / Resolve)。这一版把最后一段
接上:直接切出成片。

---

## 1. 一个不能照抄的默认值

`assemble_reel` 已经能按 `Clip` 切,所以接线本身很薄。**但不能照抄它的
`DEFAULT_CROSSFADE_S = 0.5`。**

reel 拼接的是**彼此独立的高光片段**,半秒溶解读起来是"刻意的转场"。
按文字剪正好相反:保留的两段通常是**同一句话被抠掉中间几个字**,溶解在
那里既像没人要的特效,更糟的是 —— **溶解要从两侧各吃掉时间,吃掉的正是
摄影师选择保留的那几个字。**

所以新增 `EDIT_CROSSFADE_S = 0.0`,**硬切是这里的正确默认**,调用方仍可
显式要淡入淡出。`build_montage_filter` 在 `crossfade_s=0` 时本就退化为
`concat`,已实测确认不再产生 `xfade`。

## 2. 闭环验证:把成片再喂回 ASR

这是这一版最有说服力的一步。删掉「第二,机位」后出片,**把成片重新转录**:

```
剪之前(源片): 第二，机位往左边挪一点， | 别挡住主机位。
剪之后(成片): 往左边挪一点，别挡住主机位。
  「第二」还在成片里吗:   False
  「机位往」还在成片里吗: False
  「别挡住主机位」保留:   True
```

文字编辑 → 时间区间 → ffmpeg 切 → **真实音轨里那几个字确实没了**。
时长 3.825s → 2.525s,与保留区间之和一致。

## 3. 网页端:后台线程,不阻塞 HTTP

真实婚礼素材的 ffmpeg 是**几分钟**的活。同步跑会把 HTTP 请求挂住到浏览器
或代理放弃,然后**告诉摄影师"出片失败",而它其实还在跑**。

照仓库已有的模式(上传→后台线程→轮询):`POST /video/render/<run>` 起线程
立即返回,页面每 1.2s 轮询 `/video/render_status/<run>`,完成后给
`/video/render_file/<run>` 下载。

两个细节:

- **同一个 run 已在出片时再点,不报错、也不起第二个 ffmpeg** —— 两个进程
  写同一个输出文件会互相踩;返回 `running` 即可。
- **没有任何编辑时「出片」按钮禁用** —— 否则就是把整段原片重新编码一遍,
  白等几分钟换一个和源片一样的文件。

真浏览器实测:

```
未编辑        出片按钮 disabled
剪一行后      按钮启用
点击 → 0.3s   "出片中…" ,按钮禁用
       1.5s   "成片 1.2s · 下载 mp4",按钮恢复
下载端点      HTTP 200 · 125653 字节 · video/mp4
成片转录      "别挡住主机位。"  ← 被删的第一句确实不在
```

## 4. 顺带修好一处糟糕的报错

给一个**只有转录、没有 `video_frames/`** 的 run 出片时,原本抛的是
`_resolve_frames_dir` 的「解析不出单个帧目录」。技术上没错,但对用户的
实际处境毫无帮助 —— 他的问题是**没有源片可切**,解决办法是先跑
`pixcull video`。已改成说这件事,并把原始异常附在括号里。
