### 系统性发现:**"宣传了但不工作"是这个仓库最主要的缺陷类型**

四次独立出现,每次都是**功能存在、但某条真实用户路径到不了它**:

- `pixcull library index` 报 "nothing resolvable" —— 从不查 scores.csv 的
  `path` 列,而那是 `pixcull run` 唯一会产出的来源;
- `/timeline` 缩略图全 404 —— 视频 run 不满足"是个 run"的判定;
- 浅色主题从未生效 —— 5 个页面因**定义顺序事故**从不注入 tokens;
- `pixcull export` 无输出退出 1 —— 而包描述印着 "Lightroom & Capture One
  ready"。

**共同根因:没有人走完整条用户路径。** 单元测试全绿,因为它们测的是函数,
不是旅程。

**已落地的对策**(建议继续保持):
- v2.40 的"任何命令不许是无输出 stub"守卫 —— 它自己就抓出了 `bench`;
- v2.40.2 扩到 `NotImplementedError`,抓出另外三处;
- v2.35/v2.37/v2.39 的**真实浏览器**复验(而非只看 DOM 断言);
- v2.40 的模型门禁 —— skip 不再能掩盖回归。

**仍缺的对策:一条端到端冒烟**(`run → serve → export`),在 CI 里跑。
这是本轮最值得做的工程项。

## 2. 触达维度为什么零变化(以及唯一的解法)

`pip install pixcull` **至今装不了**。轨道 v2.23 就修好了、CI 步骤就绪、
wheel 通过 `twine check` —— **只差一个 `PYPI_API_TOKEN` repo secret**。

这是全项目**投入产出比最高的一个动作**:owner 花 2 分钟,下一个 tag 自动
发版。在此之前:

- README 头条的 "pip install" 是空头支票;
- v2.31 花了一整版打包 `pixcull serve`、v2.40 又修好 `pixcull export`,
  **服务的都是一批还进不来的用户**;
- 触达分数不可能靠代码提高。

**同类第二项**:~50 条真实 keep↔maybe 分歧标注 → 解锁 rescorer
adjudicate。这个必须是 owner 亲自标(RESCORER-V3 伪造标签污染模型的教训)。

## 3. AI 剪辑开源生态调研 —— 先看许可证,再看功能

owner 点名的 **ChatCut** 有一个开源实现
[OpenChatCut](https://github.com/0xsline/OpenChatCut)(~700★)。

### ⚠️ 结论先行:**OpenChatCut 不能并入 PixCull**

它是 **AGPL-3.0**。PixCull 是 **MIT**。把 AGPL 代码 vendor 进来会**强制
整个 PixCull 转为 AGPL**,这会直接摧毁:

- `pip install pixcull` 的宽松分发预期;
- 摄影师把 PixCull 嵌进自有工作流的自由;
- 与现有 MIT 承诺的一致性。

而且它是 **Electron + React 桌面应用**,不是库 —— 技术栈与 PixCull 的
Python/本地优先完全正交。**可以作为交互设计的参考,不能作为依赖。**

### ✅ 可并入的两个(许可证干净、栈匹配)

| 项目 | 许可证 | 星 | 与 PixCull 的关系 |
|---|---|---|---|
| [FunClip](https://github.com/modelscope/FunClip)(阿里通义) | **MIT**(权重 Apache-2.0) | 高 | 补 PixCull **完全没有**的能力:ASR / 字幕 / 按文字剪 |
| [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) | **BSD-3** | 5.1k | 补**镜头切分** —— 纯库、依赖 OpenCV(PixCull 已依赖)、无重 ML |

### 这两个补的是真实缺口,不是锦上添花

我核过当前视频栈:

- **`SceneDetector` 是 CLIP 场景分类(风光/人像/…),不是镜头切变检测。**
  reel 候选是在均匀采样帧上开窗,**一个候选可能横跨一个硬切** —— 剪出来
  的片段会在中间跳一下。PySceneDetect 正好补这一刀。
- **全栈没有任何 ASR / 字幕 / 转录**(grep 无 whisper/asr/subtitle/srt)。
  而 FunClip 用的 Paraformer 是 ModelScope 上下载量超千万的中文 ASR ——
  **PixCull 本来就镜像在 ModelScope**,生态天然对齐。

### 建议的并入方式:**可选依赖,不进核心**

两者都应走 `pyproject.toml` 的 optional-dependencies(像现有的
`[face]` / `[bird]` / `[sync]`),理由:

- PixCull 刚在 v2.31 用"零编译依赖"换来了 `pip install` 的干净;
- FunClip 会拖入 FunASR + torch 生态,PySceneDetect 拖 OpenCV(已有);
- **能力缺失时必须优雅降级**,而不是 import 失败 —— 这是仓库已有的纪律
  (audio tagger 的 ONNX→DSP 回退、VLM caption 的模板回退)。

## 4. 本轮推荐(按投入产出排序)

| # | 项 | 量级 | 理由 |
|---|---|---|---|
| **①** | **owner 配 `PYPI_API_TOKEN`** | 2 分钟 | 唯一能抬触达分的动作;不做则后续所有 CLI 工作都在服务进不来的用户 |
| **②** | **端到端冒烟进 CI**(`run → serve → export`) | S | 直接针对本轮最大缺陷类型;四次事故都能被它抓到 |
| **③** | **镜头切分**(PySceneDetect,可选依赖) | S–M | 修 reel 候选横跨硬切;许可证干净、无新 ML 依赖 |
| **④** | **ASR / 按文字剪**(FunClip 路线,可选依赖) | M–L | 补一整块空白能力;与 ModelScope 生态对齐;但要先有 ③ 的边界才有意义 |
| ⑤ | 冷启动懒构建 | M | v2.38 已判定当前不划算,规模到了再说 |
| ⑥ | ANN / int8·PQ 压缩 | M | 库超 30 万张再说 |

**综合推荐从 ② 起步**:它最便宜,而且直接针对"宣传了但不工作"这个反复
出现的失效模式 —— 前四次事故里,**每一次都会被一条端到端冒烟提前抓到**。

③ 是无依赖风险的功能增量,适合与 ② 并行。④ 体量最大,且应排在 ③ 之后
(先有正确的镜头边界,按文字剪才落得准)。

## 5. 方法论说明

本轮不是 workflow 多智能体审计,是主会话据仓库实测 + 联网调研得出:

- 顺延项**逐条回归当前代码核对**(charter 会把顺延项一路抄下来,原始
  grep 结果比实际开着的多一倍);
- 开源候选**逐个查许可证**,而不是只看星数 —— 许可证是本轮唯一的**否决
  项**,并且确实否掉了 owner 点名的那个;
- 能力缺口**在代码里 grep 验证**(确认无 ASR、确认 SceneDetector 不是
  镜头检测),而不是假设。
