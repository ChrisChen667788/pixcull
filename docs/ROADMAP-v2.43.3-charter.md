## 2. 为什么审计一直没抓到 —— 这才是真正的教训

审计一直是 push 前手工 grep `git diff origin/main..main`。

**diff 范围的审计只看得见新行。** 在这个习惯建立之前就提交的内容,对它
永远不可见 —— 而这些泄露正是那样:它们再也没进过任何一次 diff,所以
每一次 push 前审计都"通过"了。

## 4. 两个设计选择,都是被误报逼出来的

第一版模式写得太宽,当场制造了三类误报 —— 每一类都指向一个更好的规则:

**① 不能禁 `/Volumes/`,要禁"你的盘"。**
`/Volumes/SSD/RAW`(输入框占位)、`/Volumes/EOS_DIGITAL`(佳能自己的卡
标签)、`/Volumes/Backup`(检查清单)全被误杀。这些不泄露任何个人信息。
改成**私有盘名黑名单**。

**② 不能禁 `/Users/<任何名字>`,要禁"本机这个用户名"。**
被误杀的是 locale 文件里十几种语言的 `/Users/you` UI 占位符,以及脱敏
功能**自己的测试桩**(`/Users/alice`)。

改成从 `Path.home()` **运行时取**用户名来匹配。这样既抓得到真实回归
(维护者把自己的路径贴进文档),又**永远不用把用户名写进仓库** ——
否则这条测试本身就成了它要防的那个泄露。CI 上 home 是构建账号,测试
平凡通过;**能泄露这个名字的机器,正是会检查它的那台机器。**

**③ `foo@2x.png` 不是邮箱**,是视网膜倍图命名;
`releases@chrischen.studio` 是 GPG 签名身份,按定义就该公开。

## 5. 明确**不动**的一类:`3J0A####.JPG`

366 处 / 15 个文件。CLAUDE.md 记着 owner 于 2026-05-29 审阅并判定这类
**佳能自动流水号文件名为非 PII**;而且其中 302 处在测试依赖的 ground-truth
CSV 里。

测试里为此专门写了一条 —— **不禁止它,而是记录这是一个决定**,并在它
扩散到未经审阅的位置时报错。这样后来的人读到的是那条裁定,而不是以为
"这个模式只是漏了"。
