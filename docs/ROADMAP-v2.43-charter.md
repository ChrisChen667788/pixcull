# v2.43 charter — 转录 + SRT + 点台词跳时间轴

DESIGN-AUDIT-2031Q1 推荐 ④,owner 定的范围:先做 (a) 转录+SRT 与
(b) 点文字跳时间轴,**(c) 按文字剪(需要编辑状态模型)留到之后**。
引擎顺序也是 owner 定的:**Paraformer 优先,Whisper 补多语**。

---

## 1. 缺口

审计在代码里 grep 过:全栈**没有任何 ASR / 字幕 / 转录**。PixCull 能告诉你
一段素材锐利、稳定、里面有笑声,但**说了什么一个字都不知道**。对拍访谈、
致辞、誓词的人,这是"哪条拍得好"和"哪条有我要的那句"的区别。

## 2. 架构:引擎可插拔,其余部分不依赖引擎

ASR 后端极其庞大 —— **FunASR 声明 71 个依赖**,而且它和 Whisper **都不给
numpy 上界**,正是 v2.42 把 numpy 拉到 2.x 弄坏 mediapipe 的同一个坑。

所以:**模型放在 extra 里,而决定"转录如何表现"的部分全是纯函数** ——
分段计时、SRT 格式化、与镜头对齐 —— 它们在**没有装任何引擎**的情况下可测、
可跑,CI 也正是这样跑的(23 条测试零引擎全过)。

| extra | 引擎 | 定位 |
|---|---|---|
| `pixcull[asr]` | Paraformer / FunASR(MIT,阿里通义) | 中文最强;权重在 ModelScope,PixCull 本来就镜像在那 |
| `pixcull[asr-whisper]` | faster-whisper | 多语覆盖更广 |

`--engine auto` 优先 Paraformer,回落 Whisper。

### 与 v2.42 不同:缺引擎是**错误**,不是静默降级

镜头切分缺失时 reel 照常工作,所以它静默降级。但 `pixcull transcribe`
**只干这一件事** —— 悄悄产出一份空转录,正是审计点名的"宣传了但到不了"。
所以缺引擎时 **exit 3 + 明确告诉你装哪个 extra**。

## 3. 与镜头边界联动(复用 v2.42)

`align_to_shots` 给每句标注它**起始所在的镜头**。刻意用起始而非中点:
一句横跨切点的话,属于它开始的那个镜头 —— 那才是编辑找这句时期待落到的
地方。

真视频实测:切点 `[3.0, 6.0]`,三句分别落在镜头 **0 / 1 / 2**,精确。

## 4. 审片台面板(b)

`/video/<run>` 右侧新增转录面板:时间戳 + 台词,**点一行跳到那一刻**,
带搜索框,播放时自动高亮当前句。用的是 `show(nearestFrame(t))` ——
**与拖动进度条、点 reel 候选完全同一个跳转原语**,所以落点一致。

样式只用共享 token(v2.37 才刚把一个自造配色的页面收回来,不能再开第四套)。

## 5. 过程中撞到的两个真问题

**(1) rich 把 `[asr]` 当样式标签吃了。** 未装引擎时的提示打印成
`pip install "pixcull"` —— **告诉用户的是错的命令**。已用 `markup.escape()`
修掉,两处。

**(2) 我自己的 `except Exception` 藏了我自己的 bug。** 服务端取转录时写了
`run["output_dir"]`,而那个处理器里的变量叫 `run_dir` —— `NameError` 被
宽 except 吞掉,页面正常渲染、面板空着、**没有任何线索**。这正是审计说的
失效模式,而我在实现它的修复时又犯了一次。

已改成 `except (OSError, ValueError, ImportError)` 并打日志:
**转录不该让页面 500,但也不该藏 bug。** 测试里钉住了 `load_transcript(run_dir)`
这个调用形式。

## 6. 一个 UI 细节

点第 3 句,高亮的却是第 2 句 —— 因为帧是采样的,最近帧(6.00s)落在那句
起点(6.10s)**之前**,而高亮是按播放头推的。点一行却亮另一行,读起来就是
bug。改成点击时把该行**钉住**,直到播放真的走过它为止。复验:点第 3/2/1 句
分别高亮第 3/2/1 句。
